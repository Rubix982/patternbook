Sync directories over SSH, sending only what changed.

ferry splits files into content-defined chunks, asks the other side which ones it already has, and ships the rest. A 2 GB build folder with one edited file moves about as many bytes as that one edit.

$ curl -fsSL ferry.sh/install | sh

Or brew install ferry, cargo install ferry-cli, or a prebuilt binary. Needs nothing on the remote except SSH and a writable home directory.

What it does

ferry does one job: make a remote directory match a local one, or the other way round. These are the things it does differently from copying with scp or rsync.

Content-defined chunks

Boundaries come from a rolling hash of the data, so inserting a line near the top of a file shifts one chunk, not all of them.

Verified by hash tree

Every sync ends by comparing a BLAKE3 Merkle root on both sides. If they differ, ferry tells you which path and refuses to report success.

Resumable

Interrupted transfers pick up from the last acknowledged chunk. Pull the cable mid-push and run the same command again.

Dry runs that tell the truth

--plan runs the full negotiation and prints exactly which files and how many bytes would move, without writing anything.

Nothing to install remotely

On first contact ferry uploads a small static helper to ~/.cache/ferry and checks its signature before running it.

Readable output

Human-friendly by default, --json for scripts. Exit codes are stable and documented, so CI can branch on them.

How a sync works

Four phases, each shown in the output so you can see where time goes.

  1. Scan and chunk

    Walk the source tree, skip anything in .ferryignore, and cut each file into 4–64 KB chunks. Results are cached by mtime and inode.

  2. Negotiate

    Send the list of chunk hashes. The remote answers with the ones it lacks, in one round trip per 50,000 chunks.

  3. Send

    Missing chunks are compressed with zstd and streamed over the existing SSH connection.

  4. Verify and swap

    Files are assembled into a staging directory, checked against the hash tree, then renamed into place atomically.

Quickstart

From install to first sync in three commands. This assumes you can already ssh into the target host.

1. Check the connection ~5s

ferry doctor opens an SSH session, installs the helper if needed, and reports what it found.

shell
$ ferry doctor deploy@atlas-01
✓ ssh          OpenSSH_9.6, key auth
✓ helper       ferry-remote 2.4.1 (installed, signature ok)
✓ disk         41.2 GB free on /srv
✓ clock skew   +0.04s

2. Preview the sync

Always safe. Nothing is written on either side.

shell
$ ferry push ./build deploy@atlas-01:/srv/atlas --plan
  modify   static/app.bundle.js        +2 chunks
  add      static/img/hero@2x.webp     +9 chunks
  delete   static/legacy.css           (use --delete to apply)
  would send 11 chunks · 184 KB

3. Run it, and save the target

Name the destination once so later syncs are just ferry push prod.

shell
$ ferry remote add prod deploy@atlas-01:/srv/atlas
$ ferry push ./build prod --delete

Commands

Every command accepts --json, -v / -q, and --config <path>. Run ferry <command> --help for the full flag list.

CommandWhat it doesCommon flags
push <src> <dest>Make dest match the local src directory.--plan --delete --exclude
pull <src> <dest>Make the local dest match a remote src.--plan --delete --since
watch <src> <dest>Push on every filesystem change, debounced.--debounce=300ms
diff <a> <b>Compare two trees by hash and list differing paths.--stat --name-only
remote add|ls|rmManage named destinations in ferry.toml.--global
doctor [host]Check SSH, helper version, disk space and clock skew.--fix
cache gcRemove unreferenced chunks from the local and remote stores.--older-than=30d

Configuration

ferry reads ferry.toml from the current directory, then ~/.config/ferry/config.toml. Project settings win. Flags on the command line win over both.

Ignore rules use gitignore syntax and can live inline or in a .ferryignore file next to the source directory.

Deletes are opt-in. Without --delete or delete = true, ferry never removes a file on the destination. The plan output lists what it skipped.
ferry.toml
# named destinations
[remote.prod]
target  = "deploy@atlas-01:/srv/atlas"
delete  = true

[remote.staging]
target  = "deploy@atlas-stg:/srv/atlas"
port    = 2222

[sync]
exclude     = ["node_modules/", "*.map", ".DS_Store"]
compression = "zstd:3"
chunk_min   = "4KiB"
chunk_max   = "64KiB"
bandwidth   = "20MB/s"   # 0 = unlimited
