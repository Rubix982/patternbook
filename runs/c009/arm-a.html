SQL for the files already on your disk.

quarry runs SQL queries over JSON, CSV, Parquet and log files without loading them into a database first. Point it at a file, a glob, or stdin, and get a table back.

$ curl -fsSL https://quarry.sh/install | sh

Also: brew install quarry · cargo install quarry-cli · other platforms

Get started Command reference
~/logs
$ quarry "SELECT status, count(*) AS hits,

         WHERE ts > now() - interval 1 hour

What it does

A query engine with no server, no schema files and no import step. The schema is inferred from the first 10,000 rows of each file, and you can override it.

Reads files in place

JSON, JSON Lines, CSV, TSV, Parquet, and common log formats (nginx, syslog, logfmt). Gzip and zstd are decompressed on the fly.

Globs and pipes

Query 'logs/**/*.jsonl' as one table, or read from stdin with - so it fits into an existing shell pipeline.

Streams, doesn't load

Rows are processed in batches, so memory stays flat on files larger than RAM. Only aggregations and sorts hold state.

Output you can reuse

Pretty tables in a terminal, and CSV, JSON, Markdown or Parquet with --format. When stdout isn't a TTY it defaults to JSON Lines.

Joins across formats

Join a CSV export against a Parquet snapshot against a log file in one query. Each source keeps its own reader.

Interactive shell

quarry shell opens a REPL with tab completion for table and column names, query history, and .schema inspection.

Quickstart

About five minutes. You need a terminal and a file to look at; the examples use a small CSV that ships with the binary.

Install and check the version

The installer puts a single binary in ~/.local/bin. Nothing else is written to your system.

$ curl -fsSL https://quarry.sh/install | sh
$ quarry --version
quarry 0.14.2 (linux-x86_64)

Look at a file's schema

Before writing a query, see what columns quarry found and which types it guessed.

$ quarry schema $(quarry sample-path)/orders.csv
order_id   BIGINT
customer   VARCHAR
placed_at  TIMESTAMP
total      DECIMAL(10,2)

Run a query

The file path is the table name. Quote it so your shell doesn't expand globs before quarry sees them.

$ quarry "SELECT customer, sum(total) FROM 'orders.csv'
         GROUP BY 1 ORDER BY 2 DESC LIMIT 5"

Send the result somewhere

Pick an output format and redirect it. Piping into another tool works the same way.

$ quarry --format parquet "SELECT * FROM 'orders.csv' WHERE total > 100" > big.parquet
$ kubectl logs api | quarry "SELECT level, count(*) FROM - GROUP BY level"

How a query runs

quarry parses your SQL, finds every file reference, and gives each one a reader for its format. Filters on a single source are pushed down into that reader, so rows that fail a WHERE are dropped before they are decoded in full.

Commands

The common ones. Every command takes --help.

CommandWhat it does
quarry "<sql>"Run a query and print the result. The default command.
quarry schema <path>Print inferred column names and types for a file or glob.
quarry shellOpen the interactive REPL in the current directory.
quarry explain "<sql>"Show the query plan, including which filters were pushed down.
quarry convert <in> <out>Rewrite a file in another format, e.g. CSV to Parquet.
quarry configPrint the resolved config and where each value came from.

Useful flags: -f, --format · --schema <file> · --sample-rows <n> · --no-header · -q, --quiet
